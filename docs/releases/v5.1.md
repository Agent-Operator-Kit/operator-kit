# Operator Kit V5.1

V5.1 returns Operator to a local, human-supervised workflow while retaining a
useful dependency graph for deciding what can run next and in parallel.

## Highlights

- one editable dependency graph per feature session;
- deterministic frontier across active features;
- capacity, dependency, lane, approval, and exact-claim checks;
- no signing authority, actor binding, Keychain, proof broker, trusted host,
  lease, fence, `launchd` relay, or heartbeat loop;
- explicit V4 and signed-V5 migration with timestamped state archive; and
- plugin version `0.5.1` with project marker `5.1`.

## Breaking change

The signed V5 control plane is not part of the V5.1 distribution. It is
preserved at tag `v5.0-signed-control-plane`. Existing signed V5 projects must
run `operator-v5-1-migrate.sh plan` and explicitly apply the reviewed migration.

## Migration

See [Migrating Operator V4 or signed V5 to V5.1](../guides/operator-v5-1-migration.md).

## Validation

The release smoke matrix covers clean bootstrap, local graph behavior, signed
state archival, version channels, role maps, plugin packaging, Cursor skills,
and Codex/Claude adapter bundles.
